## 1. 一句话定义

**上传几张照片，AI 帮你做成一本可以翻、可以拉、可以转的立体书，发给想送的人。**

## 2. 背景与机会

- 实体立体书制作门槛极高：纸艺工程、插画、模切、手工粘贴，一本书往往要设计师反复打样。
- 普通人有大量"值得做成一本书"的照片：一次旅行、一段恋爱、孩子的一年。但照片相册是平的，缺少"打开那一刻"的惊喜。
- 网页可以模拟立体书最打动人的部分：**翻开时纸片立起来**、**亲手操作的机关**、**一页比一页更惊喜的节奏**。再加上 AI 帮忙"选结构、写故事"，就可以把门槛降到"会传照片"。

## 3. 目标用户与场景

**核心用户：想做纪念书的普通人。**不懂纸艺，也不想学，只想要一本好看、有心意、能分享的书。

| 场景 | 用户 | 照片 | 他们想要什么 |
|---|---|---|---|
| 城市旅行 | 旅行者、留学生 | 地标、街景 | 把一次旅行做成"会立起来的地图" |
| 恋爱 / 表白 / 纪念日 | 情侣 | 合照、约会地点 | 一本送给对方的书，有仪式感 |
| 成长记录 | 父母 | 孩子各阶段的照片 | 按时间一页页长大 |
| 自由主题 | 任何人 | 宠物、家、毕业…… | 先做着玩，再分享 |

**不服务（V1）**：专业纸艺设计师（刀版图、精确尺寸）、多人协作、商业出版。

## 4. 产品原则

这些原则来自对几十本立体书的拆解（见研究笔记），是 AI 生成和编辑器都必须遵守的规则：

1. **结构讲故事**：折法由内容决定，不是随机的。建筑用箱形 / 手风琴，塔用十字插片，尖顶用 V 折，庆祝用放射。
2. **一本书一个母题**：像《Hearts of Love》全书只用"爱心"，每页换一种结构。母题贯穿，节奏才清晰。
3. **节奏逐页升级**：开头简单，结尾最大、最复杂、最华丽。颜色和机关也可以留到最后才"放出来"。
4. **底页即地面**：底页是一幅完整的地面画（地图、草地、桌面），立体件从中长出来。
5. **景深靠空气透视**：远处的纸片淡、冷，近处的艳、暖；每层都要镂空。
6. **真实的纸**：每张纸片都必须满足"合书不露出"（a + h ≤ 页高），能折平。网页里也不做物理上不可能的结构。
7. **克制**：文字固定在角落卡片里，每页主角只有一个，互动 1–3 个。

## 5. 立体书核心技巧（产品内置的"能力库"）

### 5.1 折法（结构）

| 折法 | 适合 | V1 | 状态 |
|---|---|---|---|
| 平行折 | 任何景片、天际线、人物 | ✅ | 已实现 |
| 十字插片 | 塔、柱、树、四面都要看的物体 | ✅ | 已实现 |
| 箱形折 | 房子、教堂、盒子、蛋糕 | ✅ | 已实现 |
| V 折 | 尖顶、主角、有棱角的物体 | ✅ | 已实现 |
| 手风琴立面 | 街道、宫殿、一排建筑 | ✅ | 已实现 |
| 放射折 / 烟花 | 庆祝、太阳、爆发、表白 | ✅ | 已实现 |
| 多层舞台 | 森林、街道纵深 | ✅ | 用多张平行折组合 |
| 跨页大拱 | 桥、彩虹、拱门 | P1 | 待做 |
| 螺旋 / 纸带 | 混乱、雨、旋风 | P2 | 待做 |
| 悬线 | 连接两个元素（思念、牵挂） | P2 | 待做 |
| 外伸纸片 | 云海、冲出画面的主角 | P2 | 待做 |

### 5.2 机关（互动）

| 机关 | 作用 | V1 |
|---|---|---|
| 拉片 | 元素沿直线移动；或驱动折法展开（点燃烟花、收起侧墙） | ✅ |
| 掀卡 / 小翻页 | 藏一句话、一个秘密、一个日期 | ✅ |
| 转盘 | 摩天轮、时钟、季节轮换 | ✅ |
| 点击触发 | 声音、动画、冒泡文字 | ✅ |
| 变身拉片 | 一拉，A 变成 B（漫威书里班纳变绿巨人） | P1 |
| 挖孔穿页 | 封面的洞穿透几页（《A Piece of Cake》） | P2 |

### 5.3 视觉

- **风格包**：水彩纸（默认）、复古地图、白模（台灯光 + 暗背景）、拼贴。V1 先做 2–3 个。
- **统一元素**：每页角落的标签卡、章节缎带、封面布面颜色。
- **颜色节奏**：可以选择"克制模式"，前面几页低饱和，最后一页才给强调色。

### 5.4 场景模板 → 结构规则

AI 和模板都用这张表来决定每页怎么做：

| 场景模板 | 底页 | 母题 / 统一元素 | 结构倾向 | 最后一页（高潮） |
|---|---|---|---|---|
| 城市旅行 | 街道地图 | 区域标签卡 + 地图路线 | 建筑按形状选折法 | 夜景 + 烟花 |
| 恋爱 / 表白 | 纯色纸或花纹纸 | 爱心母题 | 每页换一种结构表现爱心 | 唯一的红色 + 放射 |
| 成长记录 | 时间线 / 身高尺 | 年龄标签 | 每页多一层，逐年"长高" | 全家福 + 最多层 |
| 自由主题 | 照片色调的地面 | 照片说明卡 | 按照片内容自动选 | 放射或最多层 |

## 6. 核心概念与数据模型

```
Book 书
├─ id, title, subtitle, coverColor, template（场景模板）, style（风格包）, createdAt
└─ spreads[] 跨页
   ├─ title, en, story（正文）, todo（这一页可以玩什么）
   ├─ floor   底页：地图 / 纸 / 照片地面（图片或生成参数）
   ├─ backdrop 背景页：天空、远景（图片或生成参数）
   ├─ pieces[] 纸片
   │   ├─ id, x, w, a（离书脊）, h（高度）   ← 约束 a + h ≤ 52
   │   ├─ fold: parallel | cross | box | v | accordion | fan
   │   ├─ foldParams（depth, angle, segs, rays…）
   │   ├─ art: 照片剪片 / 内置素材 / 生图素材
   │   └─ tap: 点击行为（冒泡文字、动画、声音）
   ├─ controls[] 拉片：type（右 / 下）、驱动的目标（移动纸片 / 展开折法）
   ├─ flaps[] 掀卡：正面文字、背面文字
   └─ marks：角落标签卡、章节缎带
```

所有生成、编辑、导出都只操作这份数据；阅读器只负责"按数据渲染"。

## 7. 用户主流程

```
书架 ──▶ 新建 ──▶ ① 选场景模板 ──▶ ② 上传照片（排序、写一句说明）──▶ ③ 选风格
                                                                  │
                                                                  ▼
                              AI 生成大纲（书名、每页标题、结构、机关、故事）
                                                                  │
                                                                  ▼
          阅读器预览 ◀──▶ 编辑器（改文字 / 换结构 / 拖纸片 / 加机关 / 调顺序）
                │
                ▼
          导出：HTML 文件 · 视频 / GIF · 生图 prompt
```

目标：**从打开网站到拿到第一本书，不超过 3 分钟，最少只需要 3 次点击 + 传照片。**

## 8. 功能清单

优先级：**P0 = V1 必须有**，P1 = V1 尽量有，P2 = 以后。

### 8.1 书架（首页）

| 功能 | 优先级 | 说明 |
|---|---|---|
| 示例书 | P0 | 内置《伦敦》《伦敦地图》，每个场景模板至少一本示例 |
| 我的书 | P0 | 本地保存的书，显示封面缩略图、页数、修改时间 |
| 新建入口 | P0 | 醒目的"用照片做一本书" |
| 删除 / 复制 | P0 | 删除要二次确认 |
| 导入书文件 | P1 | 打开别人发来的 HTML / 备份文件，加入书架 |

### 8.2 创建向导

| 功能 | 优先级 | 说明 |
|---|---|---|
| 选场景模板 | P0 | 城市旅行 / 恋爱 / 成长 / 自由，每个附一句说明和示例图 |
| 上传照片 | P0 | 1–12 张；拖拽排序；每张可写一句说明；本地压缩到长边 1280 |
| 书名、送给谁、语气 | P0 | 可选；送给谁会出现在扉页 |
| 选风格包 | P0 | 水彩纸 / 复古地图 / 白模（V1 三选一） |
| 生成进度 | P0 | 分步提示：看照片 → 剪纸 → 选结构 → 写故事；可取消 |
| 失败兜底 | P0 | AI 不可用时，用本地算法 + 规则生成，用户说明当正文 |

### 8.3 AI 生成（通过代理后端）

| 能力 | 优先级 | 输出 |
|---|---|---|
| 照片理解 | P0 | 每张照片的主角边框、类别（建筑 / 人 / 动物 / 自然 / 物件）、有没有天空 |
| 结构分配 | P0 | 每页每个元素的 fold，遵守第 4 节原则和 5.4 规则表 |
| 节奏编排 | P0 | 自动把最适合做高潮的照片排到最后，给它最多的层和放射 / 烟花 |
| 机关分配 | P0 | 每页 1–3 个互动：拉片对象、掀卡内容、点击冒泡文字 |
| 故事文字 | P0 | 书名、每页标题、60–100 字正文、掀卡里的小秘密 |
| 生图 prompt | P0 | 每页按手册模板 T1（效果图）/ T5（分层素材）生成 prompt |
| 重新生成 | P0 | 整本重来，或单页重来、只改文字 |

### 8.4 阅读器

| 功能 | 优先级 | 说明 |
|---|---|---|
| 3D 翻开 / 合上 | P0 | 已有：舞台式视角，纸片按真实几何立起、折平 |
| 拖背景页 | P0 | 已有：往下拖看纸片折平，松手弹回 |
| 互动 | P0 | 已有：拉片、掀卡、转盘、点击 |
| 结构视图 | P0 | 已有：显示每张纸片的折法和 a、h |
| 页码、滑动翻页、键盘 | P0 | 已有 |
| 手机适配 | P0 | 竖屏可用，触控拉片顺手 |
| 自动播放 | P0 | 自动翻页 + 自动演示每个机关；也是导出视频的基础 |
| 声音 | P1 | 翻页声、机关音效，可静音 |

### 8.5 编辑器

| 功能 | 优先级 | 说明 |
|---|---|---|
| 页面列表 | P0 | 缩略图；拖拽排序；增、删、复制页 |
| 改文字 | P0 | 标题、正文、掀卡文字、标签卡文字 |
| 换照片 | P0 | 换掉后重新剪纸，其他设置保留 |
| 换结构 | P0 | 选中纸片 → 下拉选折法 → 实时预览 |
| 调纸片 | P0 | 拖动位置和高度；**自动夹紧到 a + h ≤ 52**，越界时提示 |
| 增删机关 | P0 | 给纸片加拉片、点击冒泡；增删掀卡 |
| 撤销 / 重做 | P0 | 至少 30 步 |
| 风格切换 | P1 | 整本换风格包 |
| 内置素材贴纸 | P1 | 云、鸟、船、气球、爱心、星星……一键加到页面 |
| 上传生图素材 | P1 | 把生图软件做出来的分层 PNG 放回对应的纸片 |

### 8.6 导出与分享

| 功能 | 优先级 | 说明 |
|---|---|---|
| 导出单个 HTML | P0 | 自带阅读器和照片的单文件，双击就能翻；目标 < 15 MB |
| 导出视频 / GIF | P0 | 用"自动播放"录制；MP4/WebM（竖版 9:16 和横版 16:9）+ 短 GIF |
| 导出生图 prompt | P0 | 整本的 prompt 合集（Markdown），可复制、可下载 |
| 备份文件 | P1 | 导出 / 导入可再编辑的书文件 |
| 分享短链接 | P2 | 需要云端存储，V2 再做 |

### 8.7 AI 代理后端

| 项目 | 方案 |
|---|---|
| 形态 | 无服务器函数（Cloudflare Workers 或 Vercel Functions），前端仍在 GitHub Pages |
| 接口 | `POST /api/plan`：照片（已压缩）+ 模板 + 说明 → 书的大纲 JSON；`POST /api/rewrite`：单页重写文字 |
| 模型 | Claude（带图像理解），输出严格 JSON，前端校验后再用 |
| 限流 | 按 IP / 设备每天 N 本（建议 5）；单次最多 12 张图；超限时退回本地生成 |
| 成本 | 前端先压缩图片；只传 AI 需要的分辨率；记录每次调用的 token |
| 隐私 | 后端不保存照片和结果，只转发；页面上说明这一点 |
| 安全 | API Key 只在后端；校验来源域名；内容安全过滤 |

## 9. 页面与信息架构

```
/                书架
/new             创建向导（模板 → 照片 → 风格 → 生成）
/book/:id        阅读器（含结构视图、自动播放）
/book/:id/edit   编辑器（左：页面列表；中：舞台预览；右：属性面板）
/book/:id/export 导出面板（HTML / 视频 / prompt）
```

编辑器布局（桌面）：

```
┌──────────┬──────────────────────────┬────────────┐
│ 页面列表  │       舞台（实时 3D 预览）  │  属性面板   │
│ 缩略图    │                          │  文字       │
│ 拖拽排序  │   选中的纸片有虚线框       │  结构/参数  │
│ + 新页    │   拖动改位置 / 高度        │  机关       │
└──────────┴──────────────────────────┴────────────┘
```

手机上：编辑器只做"改文字、换结构、换照片、排序"，拖动纸片放到桌面端。

## 10. 非功能需求

| 方面 | 要求 |
|---|---|
| 性能 | 中端手机翻页 ≥ 50 fps；生成一本 6 页的书（不含 AI 等待）< 15 秒 |
| 兼容 | Chrome / Safari / Edge 最近两个大版本；iOS Safari 必须可用 |
| 存储 | IndexedDB；空间不足时提示用户导出备份 |
| 隐私 | 照片默认只在本地；只有用户开启 AI 时才上传到代理后端，且不留存 |
| 可访问性 | 拉片支持键盘；尊重"减少动态效果"；文字对比度达标 |
| 工程 | 从单个 `index.html` 拆成模块（数据模型 / 渲染引擎 / 生成 / 编辑器 / 导出），用 Vite 打包，GitHub Actions 部署 Pages |

## 11. V1 范围

**V1 做：**书架、创建向导（4 个模板 + 3 个风格包）、AI 代理后端、阅读器（含自动播放）、基础编辑器、导出 HTML / 视频 / prompt。

**V1 不做（V2 以后）：**
- 账号和云端分享短链接
- 打印刀版图（实体 DIY）
- 跨页大拱、螺旋、悬线、外伸、挖孔、旋转木马等结构
- 多人协作、模板市场、商业印刷

## 12. 成功指标

| 指标 | V1 目标 |
|---|---|
| 新用户完成第一本书的比例 | ≥ 60% |
| 从进入创建到看到成书 | 中位数 ≤ 3 分钟 |
| 生成后进入编辑的比例 | ≥ 40%（说明用户愿意打磨） |
| 导出 / 分享率 | ≥ 30% 的书被导出 |
| AI 生成失败率 | ≤ 5%（失败都要能退回本地生成） |

## 14. 待定问题

1. **视频导出的实现路线**：浏览器端录制（Chrome 支持最好，iOS 受限）还是后端渲染？建议 V1 先做浏览器端，iOS 先导出 GIF。
2. **AI 代理的费用和限额**：每天每设备几本？要不要以后加付费或邀请码？
3. **照片剪纸质量**：本地算法只能剪天际线和前景。要不要在后端加"主体分割"模型，把主角抠得更干净？
4. **风格包的素材来源**：内置贴纸自己画，还是用生图手册批量生成后人工挑选？
5. **书的尺寸**：现在只有横版舞台式。是否需要竖版（适合手机全屏和小红书视频）？
